## Findings

1. Drive functions largely as a flat private artifact stream; GitHub had several historically useful but inconsistent layouts.
2. BW already pointed to many immutable GitHub commits, while other current rows still pointed only to Drive, Slack, or had no locator.
3. Historical BW `REGISTRY` must remain append-only; GitHub location/version reconciliation therefore belongs in a derived projection.
4. GitHub-first science can appear after the last BW frontier. Delivery/commit cannot be silently treated as BW ingestion.
5. Succession/currentness/restricted objects need safe pointer/hash representations, not automatic publication of packet bodies.
6. Concurrent/fallback writers can create multiple GitHub bodies for one logical artifact.
7. Public-source traceability requires bidirectional identity:
   `GitHub artifact -> BW event/status` and `BW public artifact -> immutable GitHub path/commit or explicit pending state`.

## Forward repository rule

New full public-safe science:
`research/<lineage>/<YYYY-MM-DD>/<artifact>.md`

Pointer/hash/legacy record:
`archive-index/<YYYY>/<lineage>/...`

Public-safe succession pointer:
`succession/<YYYY>/<lineage>/...`

Cross-surface projection:
`manifests/cross-surface/current.json`

Historical paths remain valid provenance.

## Historical backfill priority

Older material before the reconciled active tail should be migrated incrementally by stable identity and reuse value, in this order:

1. load-bearing/current BW artifacts with no GitHub body or safe pointer;
2. GitHub scientific artifacts with no BW ingestion/status;
3. duplicate logical artifacts with multiple HEAD bodies;
4. executable results lacking reproduction manifests;
5. historical packets only where retrieval/reuse value justifies a pointer or public-safe body.

```text
GITHUB_COMMIT != BW_EVENT
DELIVERY != INGESTION != SCIENTIFIC_ACCEPTANCE
SYNCED != SCIENTIFIC_VALIDATION
COPY != NEW_ARTIFACT
PUBLIC_GITHUB != PRIVATE_IW_COMMONS
```
