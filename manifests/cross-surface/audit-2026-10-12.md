# Drive ↔ GitHub ↔ BW reconciliation audit — 2026-10-12

## Scope

This is a bounded repository/custody audit, not a scientific review.

Drive root scan inspected the first 1000 accessible items returned by the connector:
- 945 native Google Docs;
- 54 raw files;
- 1 folder;
- 687 titles beginning with `IW_`;
- 992 items matching broad project-like naming.

Because the connector scan was capped at 1000, these numbers are a lower-bound inventory, not a claim that the whole accessible Drive contains exactly 1000 items.

## Findings

1. Drive behaves largely as a flat artifact stream; GitHub already contained several incompatible but useful historical layouts.
2. BW already mapped many recent GitHub artifacts to immutable commits, but historical `source_primary_locator` rows may still point to Drive even after a later GitHub mirror exists.
3. Therefore historical REGISTRY rows must remain append-only; cross-surface location/version state belongs in a derived projection.
4. Some public-safe BW/Drive artifacts were missing full GitHub bodies.
5. Some private succession/currentness artifacts need public-safe pointers, not body publication.
6. GitHub-first scientific commits can appear after the last BW frontier and must remain `GITHUB_PENDING_BW_INGEST`.
7. Concurrent writers created at least one duplicate full GitHub body for the same logical artifact (XH-S3 donor harvest 025).

3. duplicate logical artifacts in multiple GitHub HEAD paths;
4. executable results lacking reproduction manifests;
5. older historical material only when retrieval/reuse value justifies migration.
