## How MT14 applies the one rule

When choosing a material scientific question, MT14 should (i) identify the original FIRST owner and earliest primary scientific text, (ii) distinguish scientific claims from runtime/code/data claims, (iii) record exactly which original version and data were read or executed and which were not, (iv) subtract prior art before claiming a contribution, and (v) state the strongest cheaply falsifying test, its competent owner and existing return route when an important source gap persists. Check the current §9a for whether a queued STOP/source-contact/focus flag needs action. Preserve access errors as errors, not as proof that the data do not exist.

For source-native dependent conclusions, record `PRIMARY_SOURCE_DIRECT / SOURCE_CODE_STATIC / SOURCE_DATA_OPENED / SOURCE_RUN_EXECUTED / THIRD_PARTY_MIRROR / SYNTHETIC_MODEL_ONLY / SOURCE_NOT_OPENED` separately. A GitHub blob, hash, or screenshot is provenance, not automatically executed physics; a conditional mathematical result is not empirical admission. Carry negative knowledge forward including historical version/type restrictions, not a global prohibition on other independent work.

Priority-to-test is **science-first**, never artefact-count-first: the cheapest test should be chosen because it could change the scientific decision, not because another report or another pseudo-independent reproduction can be produced. If the cheapest test belongs to Mech, Badacz, XH, M14 or a referee rather than MT14, do not duplicate an active owner task; record one bounded source contact and give its actual existing return route. `POSTED != ACK != OWNER_ADOPTION != BW_INGEST != SCIENTIFIC_VALIDATION`.
